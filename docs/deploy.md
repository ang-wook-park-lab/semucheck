# 배포 안내 (Railway + Postgres 기준)

저장소 루트의 `Dockerfile`, `railway.json`, `deploy/`(서버)가 배포 구성입니다. Railway에서 이 저장소를 연결하면 빌드·실행됩니다. Render, Fly.io 등 Docker를 받는 호스트에서도 같은 구성으로 동작합니다.

## 한눈에 보기
| 항목 | 내용 |
|---|---|
| 빌드 | 저장소 **루트**의 `Dockerfile` (Vite 빌드 → 서버 이미지) |
| 실행 | `node server.mjs` (`PORT` 환경변수 사용) |
| 헬스체크 | `/healthz` (200) |
| 저장소 | `DATABASE_URL`이 있으면 **Postgres**, 없으면 데모 모드(브라우저 저장) |
| 로그인 | 앱 화면의 **아이디 + 비밀번호** 하나뿐입니다(브라우저 팝업 로그인 없음, 이메일 가입 없음). |
| 주의 | **Root Directory를 `web`으로 지정하지 마세요.** `web/`이 `../checklists` 데이터를 읽기 때문에 빌드가 깨집니다. |

## 서비스 변수 (Railway → semucheck 서비스 → Variables)

| 변수 | 값 | 설명 |
|---|---|---|
| `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` | Railway Postgres 연결. 값 칸에 그대로 입력하면 같은 프로젝트의 Postgres 서비스 주소가 자동으로 채워집니다. 서비스 이름이 `Postgres`가 아니면 그 이름으로 바꾸세요. |
| `ADMIN_PASSWORD` | (선택) 8자 이상 | **계정이 하나도 없을 때만** 만들어지는 최초 관리자의 임시 비밀번호. 정하지 않으면 무작위 임시 비밀번호가 만들어져 **배포 로그에 한 번만** 출력됩니다. |
| `ADMIN_USERNAME` | (선택) 기본 `admin` | 최초 관리자 아이디(영문 소문자·숫자·`.` `_` `-`, 3~30자). |
| `ADMIN_RESET` | `true` (비상용) | 관리자 비밀번호를 잊었을 때만. 아래 "비밀번호를 잊었을 때" 참고. 복구 후에는 반드시 지우세요. |
| `DATABASE_SSL` | `true` (선택) | 공개 주소(`...proxy.rlwy.net`)로 연결할 때만. 같은 프로젝트의 내부 주소(`postgres.railway.internal`)는 필요 없습니다. |

변수를 저장하면 Railway가 자동으로 다시 배포합니다. 예전에 쓰던 `SITE_PASSWORD`, `SITE_USER`, `ALLOW_SIGNUP` 변수는 **더 이상 쓰이지 않습니다**(남아 있어도 무시되므로 지우세요).

## 계정과 로그인

**가입 기능은 없습니다.** 계정은 관리자가 직접 만듭니다.

1. **최초 관리자**: 서버가 시작할 때 계정이 하나도 없으면 관리자 계정(`admin`)을 만듭니다. 임시 비밀번호는 `ADMIN_PASSWORD`, 없으면 배포 로그(`임시 비밀번호: ...`)에서 확인합니다.
2. 이 아이디로 처음 로그인하면 **비밀번호 변경 화면**이 먼저 나옵니다. 본인 비밀번호를 정해야 다른 화면을 쓸 수 있습니다.
3. 관리자는 **관리자 → 사용자 · 샘플 관리**에서 **이름 · 아이디 · 임시 비밀번호 · 역할**(관리자/컨설턴트/고객)을 입력해 계정을 만듭니다. 고객 계정은 연결할 고객사도 고릅니다.
4. 아이디와 임시 비밀번호를 본인에게 전달합니다. 본인이 **처음 로그인할 때 비밀번호를 바꿔야** 시작할 수 있습니다. 관리자가 나중에 비밀번호를 다시 정해 주면 그것도 임시 비밀번호가 되어 다음 로그인 때 다시 바꾸게 됩니다.
5. 화면 **왼쪽 위**에 로그인한 사람의 이름과 역할이 표시됩니다.

아이디는 영문 소문자·숫자·`.` `_` `-`로 3~30자이며 대소문자를 구분하지 않습니다. (이메일로 만들었던 예전 계정은 그 이메일이 그대로 아이디가 되어 계속 로그인할 수 있습니다.)

### 역할별 권한
| 역할 | 볼 수 있는 것 | 할 수 있는 것 |
|---|---|---|
| 관리자 | 모든 고객사·진단·사용자 | 모든 데이터 수정, 사용자 관리, 체크리스트 수정·엑셀 교체, 샘플 데이터 관리 |
| 컨설턴트 | **본인 담당** 고객사·진단만 | 본인 데이터 입력·수정, 체크리스트 조회·엑셀 다운로드 |
| 고객 | 연결된 자기 회사의 **완료된** 보고서만 | 읽기 전용(엑셀로 보고서 내려받기) |

권한은 서버가 판단합니다(화면은 안내용). 계정을 비활성화하면 그 사용자의 로그인이 즉시 풀립니다.

### 비밀번호를 잊었을 때
- 일반 사용자: 관리자가 **사용자 수정**에서 새 임시 비밀번호를 정해 줍니다. 본인이 다음 로그인 때 바꿉니다.
- **관리자 본인**: Railway 변수에 `ADMIN_USERNAME`(관리자 아이디), `ADMIN_PASSWORD`(새 임시 비밀번호 8자 이상), `ADMIN_RESET=true`를 넣고 재배포하면 그 계정의 비밀번호가 재설정됩니다(없으면 새로 만듭니다). 로그인해 비밀번호를 바꾼 뒤 **`ADMIN_RESET`과 `ADMIN_PASSWORD` 변수를 지우세요.** 남겨 두면 재배포할 때마다 다시 재설정됩니다.
- 이메일로 비밀번호를 재설정하는 기능은 없습니다.

## 샘플 데이터
첫 관리자가 생기면 **가상의 샘플 고객사 3곳과 진단 9건**이 자동으로 한 번 들어갑니다(`[샘플]` 표시). 관리자는 **사용자 · 샘플 관리** 화면에서 샘플을 다시 넣거나, 권한 확인용 **샘플 컨설턴트·고객 계정**(`sample-consultant`, `sample-client`)을 만들거나, 모두 지울 수 있습니다. 샘플 계정의 비밀번호는 만들 때 무작위로 정해져 **한 번만** 화면에 표시되고 어디에도 저장되지 않습니다. 실제 운영 전에는 샘플을 지우세요.

## 엑셀 업로드·다운로드
- **체크리스트**(분야별): 내려받기는 모든 사용자, 수정·업로드는 관리자만. 올리기 전에 변경 요약과 오류(행 번호)를 미리보기로 보여 주며, 오류가 있으면 아무것도 바뀌지 않습니다. 업로드하면 그 분야의 체크리스트를 **통째로 교체**합니다(기본값으로 되돌리기 가능).
- **고객사**: 등록 양식 내려받기·일괄 등록(컨설턴트는 본인 담당으로, 관리자는 담당자 아이디 지정 가능).
- **진단 응답**: 진단 화면에서 양식을 내려받아 채운 뒤 올립니다.
- **보고서**: 엑셀로 내려받기.
- 엑셀의 수식은 계산하지 않고, 올린 값은 모두 서버·브라우저에서 한 번 더 검사합니다.

## 간단진단
각 분야에는 **전체 진단**과 문항이 적은 **간단 진단**이 있습니다(왼쪽 메뉴의 "간단 진단"). 간단 진단에는 판정에 결정적인 문항과 그 조건 문항이 항상 포함됩니다. 관리자는 체크리스트 관리에서 어떤 문항을 간단 진단에 넣을지(엑셀의 `간단진단` 열) 바꿀 수 있습니다.

## Railway에서 처음 배포하기
1. https://railway.com 에서 **New Project → Deploy from GitHub repo**를 고르고 `ang-wook-park-lab/semucheck`을 선택합니다. 저장소가 목록에 없으면 Railway의 GitHub 앱에 접근 권한을 줘야 합니다.
2. 같은 프로젝트에 **Database → Add PostgreSQL**을 추가합니다.
3. 위 변수(`DATABASE_URL`, 필요하면 `ADMIN_PASSWORD`)를 semucheck 서비스에 입력합니다.
4. **Settings → Networking → Generate Domain**으로 주소를 만들고 접속해 `admin`으로 로그인합니다.
5. 화면 상단에 "데모 모드" 표시가 보이면 `DATABASE_URL`이 연결되지 않은 것입니다. 변수와 배포 로그("DB 연결 완료")를 확인하세요.

## 공개 범위에 대한 주의
이 앱은 접속 전 비밀번호 단계가 **없습니다.** 앱 로그인은 고객 데이터(고객사·진단)와 화면 흐름을 지킬 뿐, 체크리스트 문항·권고·근거 조문은 **브라우저로 내려가는 JS 번들 안에 들어 있어** 주소를 아는 사람은 로그인 없이도 번들을 내려받아 내용을 읽을 수 있습니다. 문항은 책을 바탕으로 정리한 내용이므로, 공개해도 되는 범위인지 확인하세요. 주소를 널리 알리지 않는 것이 좋습니다.

## DB 모드가 하는 일
- 시작할 때 테이블을 **자동으로 만들고 필요한 변경(마이그레이션)을 적용**합니다. 별도 작업이 필요 없습니다.
- 비밀번호는 `scrypt` 해시로만 저장하고, 로그인 세션은 HttpOnly 쿠키(14일)이며 서버에는 토큰의 해시만 남습니다.
- 로그인 실패가 15분에 10회를 넘으면 해당 아이디·접속지의 로그인을 잠시 막습니다.
- DB에 연결하지 못하면(5회 재시도 후) 서버가 종료됩니다. 데모 모드로 조용히 떨어지면 데이터가 브라우저에만 저장되기 때문입니다. 배포 로그에서 원인을 확인하세요.
- **백업**: Railway Postgres 서비스의 백업 기능(또는 `pg_dump`)을 켜 두세요. 고객 데이터가 이 DB에만 있습니다.

## 데모 모드와 Supabase
- `DATABASE_URL`도 Supabase 변수도 없으면 **데모 모드**입니다. 계정·고객사·진단이 각자 브라우저에만 저장되므로 화면 확인용이며, 이 모드에서만 화면에서 직접 계정을 만들 수 있습니다(권한 구분 없음).
- Postgres 대신 Supabase를 쓰고 싶다면 `web/README.md`의 "Supabase 설정"을 따르고 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`를 넣어 다시 배포하세요(빌드 시점 변수). 이 모드는 이메일 로그인이며 위의 역할·사용자 관리 기능은 서버 DB 모드에서만 동작합니다.

## 로컬에서 확인
```bash
# Docker가 있을 때 (저장소 루트에서)
docker build -t semucheck .
docker run --rm -p 3000:3000 semucheck   # http://localhost:3000 (DB 없는 데모 모드)

# Docker 없이 (DB 없는 데모 모드)
cd web && npm install && npm run build && cd ../deploy && npm install && cd ../web && npm run serve

# DB까지 붙여서 (첫 실행 때 admin / 지정한 임시 비밀번호가 만들어집니다)
DATABASE_URL=postgresql://사용자:비밀번호@localhost:5432/DB이름 ADMIN_PASSWORD='임시비밀번호8자이상' npm run serve
```

## 서버 환경변수 요약
`PORT`(호스팅이 주입), `DATABASE_URL`, `DATABASE_SSL`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `ADMIN_RESET`, `STATIC_DIR`(기본: `./dist` 또는 `../web/dist`), `VITE_SUPABASE_URL`(런타임에는 CSP 허용 주소 계산에만 사용).

## 보안 헤더
서버가 CSP(`script-src 'self'` 등), `X-Frame-Options: DENY`, `X-Content-Type-Options`, `Referrer-Policy`, HTTPS 접속 시 HSTS를 붙입니다. 상태를 바꾸는 API 요청은 같은 출처의 요청만 받습니다(CSRF 방어).

## 다른 호스트
- **Render / Fly.io**: 저장소 루트의 Dockerfile을 지정하고 위 환경변수를 넣으면 됩니다(포트는 `PORT`).
- **Vercel**: 서버가 없어 DB 모드(계정·역할 기능)를 쓸 수 없습니다. 쓰려면 Supabase를 따로 써야 합니다.

## 개발자용
- 서버 테스트: `cd web && npm run test:deploy` (정적 서빙, SPA 대체, 경로 이탈 차단, 팝업 로그인 없음, gzip, 보안 헤더)
- API 테스트(Postgres 필요, 테스트용 DB만 가리키세요): `TEST_DATABASE_URL=postgresql://... node --test deploy/api.test.mjs` — 최초 관리자·임시 비밀번호 강제 변경·역할별 권한·담당 범위·체크리스트 수정·샘플·CSRF·입력 검증·세션 만료. DB 주소가 없으면 건너뜁니다.
- 이미지 빌드 단계는 개발 환경에서 직접 실행해 보지 못했습니다(Docker 데몬 없음). 대신 Dockerfile과 같은 순서·같은 파일 배치로 빌드해 실행한 결과를 검증했습니다.
